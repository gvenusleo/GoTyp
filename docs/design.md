# GoTyp 设计

本文是 GoTyp 唯一的产品与架构设计文档。改变产品边界、数据格式、UI 技术路线、保存语义或 Typst 渲染方式时，先改本文，再改实现。

## 产品

GoTyp 是本地桌面笔记应用。用户打开一个文件夹作为笔记仓库（Vault），在单窗口中编辑 Markdown 或 Typst 源码并查看原生预览。仓库中的其他文件也列在文件树里：纯文本直接编辑，图片原生显示，其余格式交给系统默认应用。

- 打开、新建、切换、重命名、删除和保存 `.md`、`.markdown`、`.typ` 笔记
- 启动时回到上次的仓库和文件，`⌘P` 按文件名、路径和笔记标题快速打开仓库中的任意文件
- 两种笔记和其他纯文本文件共用一个源码编辑器，保存与冲突规则相同；非笔记文本只有编辑模式
- 图片（PNG、JPEG、GIF、WebP、SVG）只读显示；无法以文本打开的文件显示「在默认应用中打开」
- Markdown 支持编辑、分屏和预览模式
- Typst 的预览、诊断、编辑辅助和 PDF 导出都由 tinymist 提供：实时预览与双向滚动同步，编辑器内诊断，补全、悬停、跳转定义、格式化、重命名和标题跳转
- 自动保存不写坏原文件，不静默覆盖外部修改
- 监听仓库变化，侧栏和未修改的当前笔记跟随磁盘内容
- 界面和 Markdown 预览由 MyGo Native UI 绘制；只有 Typst 预览区嵌入 WebView，显示 tinymist 的预览页

不提供云同步、协作和账户体系。

## 技术基线

- Go `1.27.3`，MyGo 版本以 `go.mod` 为准，应用标识 `xin.liuyu.gotyp`
- tinymist（内置 Typst `0.15.1`），通过 stdio 上的 LSP 通信，是唯一的 Typst 依赖；不调用 Typst CLI，不引入 Typst 绑定或 Rust 库

`tinymist` 从 `PATH` 查找，不自动下载或捆绑。从图形界面启动时进程拿不到 shell 的 `PATH`，因此启动时把 `/opt/homebrew/bin`、`/usr/local/bin`、`~/.cargo/bin`、`~/.local/bin` 和 mise shims 目录中尚未包含的追加到 `PATH` 末尾（Windows 除外），不启动 shell 读取配置。

升级 MyGo 或 tinymist 后，重新核对本文涉及的 API、命令输出和协议行为。

## 固定决策

- 每篇笔记只用一种语法，由扩展名决定；不做 Markdown 与 Typst 的混排或互转
- 原始文本文件是唯一事实来源
- 单窗口文件夹仓库，不采用一篇笔记一个窗口的文档模型，因此不使用 `mygo.NewDocuments`
- 编辑器使用 `ui/editor`，Markdown 预览使用 `ui/markdown`，Typst 预览用 `ui.WebView` 显示 tinymist 的预览页，不自己渲染页面
- PDF 只用于导出，不内嵌 PDF 阅读器
- Typst 编辑辅助只接 tinymist，不设计通用 LSP 层、渲染插件接口或第三方 UI 组件

## 首版不做

富文本所见即所得、混合渲染、标签与双链、全文搜索、多标签页、云同步与插件、附件管理、未落盘编辑的崩溃恢复。tinymist 中不接入的能力见「Typst 编辑辅助」。

## 界面

界面风格参考 Linear：极简、紧凑，只用中性灰阶、细分隔线和少量图标区分层次，不放解释性文字。

- 视觉参数集中在 `internal/gui/theme.go`，强调色跟随系统；编辑器和 Markdown 代码块的语法色沿用 MyGo 默认配色，这里只调整编辑器底色、当前行、行号和诊断色；Markdown 预览的版式在这里显式给出
- 选中、悬停和按下都用文字色叠在底色上的中性浅底，强调色只用于光标、选区和焦点
- 只使用 MyGo 原生组件，不用 `ui.Painter` 或着色器绘制业务 UI，不自定义 Markdown 文档组件
- 图标使用内嵌的 Lucide 图标集（`internal/gui/icons`），纯图标按钮必须设置 `Label` 和 `Tooltip`
- Typst 语法高亮通过 `editor.Language` 分词器实现，行状态记录块注释、原始文本、跨行公式和括号嵌套

窗口隐藏系统标题栏，侧栏延伸到红绿灯下方，内容区顶部的文档头兼作标题栏：

```text
┌──────────────────┬───────────────────────────────────────────┐
│ ● ● ● ◧          │ notes / reading.md •           ✎ ◫ ◉   ⋯  │
│ 📁 仓库名       ⇅ ├───────────────────────────────────────────┤
│ ＋ 新建           │ 源码编辑器              │ 预览              │
│ 🔍 搜索        ⌘P │                                           │
│ ▾ notes           │                                           │
│   📄 reading.md   │                                           │
│                  ├───────────────────────────────────────────┤
│ ⚙                │ ✓ 12 ms                第 12 行，第 4 列  1,234 字 │
└──────────────────┴───────────────────────────────────────────┘
```

- 侧栏：宽度 180 到 420 DIP，默认 248，内容区至少留 360；`⌘B` 收放。顶部是仓库切换，其下是「新建」（弹出新建菜单）和「搜索」（打开快速打开）两个入口，再往下是 `ui.Outline` 文件树，左下角是设置按钮。目录行不画展开箭头，只有文件夹图标（展开时 `folder-open`，收起时 `folder`）和名称，点击整行展开或收起；每深一层缩进一个图标的宽度，同一层的目录与文件图标纵向对齐；文件图标按扩展名取 Lucide 的 `file-*` 系列（笔记、代码、JSON、配置、脚本、图片、音频、视频、压缩包、表格），其余用 `file`。右键提供新建、重命名、复制路径、在默认应用中打开、在文件管理器中显示、移到废纸篓
- 文档头：左侧目录和文件名，未保存时显示圆点；右侧是编辑、分屏、预览分段（`⌘1`、`⌘2`、`⌘3`，只对笔记显示）和「更多」菜单。分屏宽度不足时改为上下布局
- Typst 编辑命令放在原生「编辑」菜单和编辑器右键菜单中：跳转到定义（`F12`）、重命名符号（`F2`）、格式化文档（`⇧⌥F`）、跳到标题（`⇧⌘O`）；当前不是 Typst 笔记或 tinymist 不可用时禁用
- 状态栏：28 DIP 高。左侧是 Typst 诊断状态（错误或警告计数，点击展开诊断面板）和后台活动；右侧是光标位置或选区、字数。平时用次要文字色，只有错误和警告着色
- 冲突和保存失败用编辑区上方的常驻提示行展示，并提供对应操作
- 设置：侧栏左下角的设置按钮或 `⌘,` 打开应用内设置面板，左侧是分类，右侧是该分类的各项，右上角是关闭按钮。分类有「外观」和「预览」。「外观」是主题（浅色、深色、跟随系统）、界面字体、代码字体，以及按当前字体排版的预览；「预览」是深色主题下 Typst 预览是否调色（默认不调色）。选中即生效并保存，没有保存按钮；不提供配色设置。界面字体用于界面和 Markdown 正文，代码字体用于编辑器、Markdown 代码和 Typst 诊断；字体列表在后台读取
- 新建笔记不弹对话框，在当前目录创建「未命名」笔记；重命名用应用内对话框，只改文件名；删除移到系统废纸篓，不弹确认
- 专注模式隐藏侧栏、文档头和状态栏，只在会话内有效
- 打开仓库、另存为副本和导出 PDF 使用系统文件对话框；窗口尺寸和位置由 MyGo 保存
- 动效只用于反馈，不推动预览页面

## 数据

Vault 是普通文件夹，GoTyp 不向其中写入任何自己的文件。应用状态保存在用户配置目录的 `GoTyp/state.json`，包括外观与预览设置、最近仓库，以及按仓库区分的当前笔记、编辑模式、侧栏、分栏比例和行号设置；文件损坏时回到默认状态，不认识的主题按跟随系统处理。tinymist 导出 PDF 的临时文件放在系统临时目录下按进程号命名的目录中，导出后立即删除，下次启动时清理已不存在进程的目录。

- 文件 ID 是相对 Vault 根的规范化路径，统一用 `/` 分隔
- 扫描列出全部文件，只有 `.md`、`.markdown`、`.typ` 是笔记
- 以文本打开的文件不超过 10 MiB，且是不含 NUL 的合法 UTF-8；否则不进编辑器，避免保存时改坏非文本内容。笔记同样适用
- 图片不超过 20 MiB，在后台解码，长边缩到 4096 像素以内
- 笔记标题取第一个一级标题（Markdown `#`、Typst `=`），没有时用文件名，只用于快速打开匹配；只读文件开头 4 KB
- 扫描忽略以 `.` 开头的条目，跳过无法读取的目录，不跟随逃出 Vault 的符号链接
- 用 `mygo.WatchFiles` 递归监听：结构变化时后台重新扫描；当前笔记被外部修改时，无未保存编辑就静默重载，否则进入冲突；自己保存产生的事件按文件状态识别并忽略
- 重命名只在同一目录内进行，目标已存在时拒绝；扩展名可以改，改后按新扩展名决定打开方式

## 保存与冲突

保存写入 `editor.Buffer` 的不可变快照，文件 I/O 在后台执行。

- 停止编辑 1 秒后自动保存，持续编辑时最迟 10 秒保存一次；手动保存、切换笔记、关闭和退出时立即保存
- 写入同目录临时文件后原子替换，保留原文件权限，替换后同步目录
- 保存结果携带开始时的 buffer 版本，只有该版本仍是当前版本才标记为已保存
- 写入失败时保留编辑并提示，5 秒后重试
- 每次读取或保存后记录文件标识、修改时间和大小，保存前重新核对。不一致时进入冲突，停止自动保存，由用户选择重新加载、覆盖或另存为副本；文件被删除时可重新创建、关闭或另存为副本
- 切换、重命名或删除当前笔记前先在后台保存，失败则留在原笔记。退出时保存失败，用系统对话框询问取消还是放弃修改

原子替换只防止写出半截文件，不提供崩溃恢复。

## 编辑状态与异步任务

当前笔记维护一个编辑会话：笔记 ID、类型、`editor.State`、buffer 版本、已保存版本、保存状态和预览状态。图片或无法以文本打开的文件没有编辑会话，只保存文件 ID 和后台读取的结果。

- `editor.State`、列表状态和预览数据保存在应用状态中，不保存 `ui.Element` 或 `*ui.Context`
- 有状态控件使用笔记路径等稳定 key
- view 中不做 I/O、编译或解码，也不无条件启动任务
- 后台任务只读快照，结果经 `Window.Update` 回到主线程，应用前核对笔记 ID 和源版本，过期即丢弃
- 窗口关闭、切换笔记或新任务到来时取消不再需要的工作

## Markdown 预览

预览读取当前编辑快照，使用 `markdown.View` 默认组件，阅读宽度约 720 DIP 居中。版式接近 GitHub：一、二级标题下有横线，标题、段落和列表间距与 GitHub 相近，代码块无边框，表格隔行着色；链接仍用系统强调色。悬停文档沿用紧凑的 Markdown 主题。语法支持 GFM、脚注和 GitHub Alert；不解析 @提及和 #引用。数学公式暂不渲染，按 TeX 源码显示。本地图片通过 `markdown.FileImages` 按笔记目录解析，不下载远程图片。

链接处理：页内锚点交给 Markdown 组件；Vault 内的笔记在 GoTyp 中打开；`http`、`https`、`mailto` 和 Vault 内其他文件交给系统打开；不存在、逃出 Vault 或无法识别的目标只提示错误。

## tinymist

预览、诊断、编辑辅助和 PDF 导出都由 tinymist 提供。tinymist 缺失或停用时，Typst 笔记仍可编辑和保存，只是没有这些能力；预览区显示错误。

- 进程：每个仓库最多一个 `tinymist lsp`，首次打开 Typst 笔记时启动，`rootUri` 为 Vault；`exportPdf` 设为 `never`，`outputPath` 指向 GoTyp 的临时目录，`formatterMode` 设为 `typstyle`，关闭未使用的能力；服务端请求都要回应，`window/showDocument` 交给滚动同步处理，其余回应空结果。意外退出后重启一次，再失败就停用到下次打开仓库
- 同步：打开笔记时 `didOpen`，随后执行 `tinymist.focusMain` 把主文件切到这篇笔记，否则 tinymist 只跟随第一次打开的文档，之后的笔记收不到诊断；切走或删除时 `didClose`。编辑停止 150 毫秒后发送全量 `didChange`，补全或悬停前若 buffer 版本更新也先发送；这些通知在同一后台队列按序执行，比已发版本旧的快照直接放弃。tinymist 只读内存中的 buffer，不需要先保存或写临时文件
- 坐标：tinymist 使用 UTF-16 行列，编辑器使用 UTF-8 字节偏移，换算在 `internal/tinymist` 中基于对应版本的快照完成；越界或落在字符中间时丢弃整次结果

## Typst 预览

预览区嵌入一个 WebView，显示 tinymist 预览服务提供的页面。相对资源按笔记在 Vault 中的位置解析，项目根固定为 Vault。

- 任务：Typst 笔记首次显示预览时，执行 `tinymist.doStartPreview`，参数为 `--task-id`、`--data-plane-host 127.0.0.1:0`、`--not-primary`、`--no-open` 和主文件路径；`--not-primary` 让每个任务用独立的编译实例，否则主实例的预览会把主文件钉住，结束任务后也不解除，之后切换的笔记会退回磁盘内容并失去诊断；返回的 `staticServerPort` 拼成 `http://127.0.0.1:<端口>/` 交给 WebView 加载。切换笔记、关闭仓库、退出或调色状态变化时用 `tinymist.doKillPreview` 结束旧任务
- 核对：启动结果回到主线程时，笔记 ID 和任务代次都匹配才加载；不匹配说明期间已切换笔记，直接结束这个任务
- WebView：每个窗口一个，由 `Window.NewWebView` 创建并保存在应用状态中，view 只用 `ui.WebView` 放置；不显示预览时不构建该元素，页面保留。背景色取主题的预览画布色，避免加载前闪白。不给预览页绑定 Go 方法；离开预览服务地址的导航一律取消，`http`、`https`、`mailto` 链接交给系统打开
- 编译：预览页随 `didChange` 增量刷新，编译失败时保留上一次成功的渲染。诊断来自 `textDocument/publishDiagnostics`，预览实例与主实例对同一处的重复报告合并为一条；状态栏显示错误和警告计数，诊断面板逐条列出
- 缩放：使用预览页自带的交互，GoTyp 不提供缩放菜单和快捷键
- 编辑器到预览：光标所在行变化并停留 300 毫秒后，执行 `tinymist.scrollPreview`，事件为 `panelScrollTo`，把预览滚到对应位置；多处选区或预览不可见时不发送
- 预览到编辑器：在预览页中点击文字，tinymist 发来 `window/showDocument`。目标是当前笔记时移动光标并滚动到该处，回应成功；其他文件按跳转定义的规则处理；结果在主线程核对笔记 ID 后应用
- 深色：设置中打开调色后，深色主题下启动任务时加参数 `--invert-colors`，取值 `{"rest":"always","image":"never"}`，反转版面而保留插图；浅色主题和没有打开调色时不加。主题或开关变化时重启预览任务。PDF 导出不受影响

预览服务只监听 127.0.0.1 的随机端口，没有鉴权，本机其他进程能连上并读到渲染内容；这与 tinymist 编辑器扩展的做法一致，GoTyp 面向用户自己的机器，接受这一点。`doStartPreview` 的参数、返回字段和预览页行为都不是稳定接口，升级 tinymist 后需重新核对。

## Typst 编辑辅助

使用 `editor.State` 已有的钩子和显示能力，不自绘浮层。结果按笔记 ID 和 buffer 版本核对，过期即丢弃；坐标按「tinymist」一节换算。

- 补全：前缀含非 ASCII 字符时不自动请求，`Ctrl+Space` 可主动请求。`textEdit` 起点须与编辑器起点一致，否则裁剪或丢弃；片段用 `editor.ParseSnippet` 解析；`Documentation` 只放第一段纯文本摘要；按 `sortText` 稳定排序；光标位置变化后丢弃
- 悬停：结果用 `markdown.View` 显示
- 诊断：当前笔记的诊断经 `SetDiagnostics` 在编辑器中画波浪线，悬停显示内容，滚动条上有标记。tinymist 的诊断不带版本号，`SetDiagnostics` 的版本只能取诊断到达时已发给 tinymist 的 buffer 版本，编辑器据此把位置映射到之后的编辑；上一次编译的诊断晚于新的 `didChange` 到达时，位置会短暂偏移，下一次编译后纠正。tinymist 每次编译都重发诊断，与已显示的相同时界面不重排；是否相同只在界面判断，切换笔记清空诊断后，被引入文件的同一条错误要重新显示。其他文件的诊断只在诊断面板中列出
- 跳转定义：`OnDefinition`（`⌘` 点击或 `F12`）请求 `textDocument/definition`。目标在当前笔记时移动光标；在仓库内其他文件时按切换规则先保存，再打开并定位；在仓库外（如 Typst 包）时提示无法打开
- 格式化：`textDocument/formatting`，使用 tinymist 内置的 typstyle，缩进与编辑器一致。只手动触发，不在保存时自动格式化；结果作为一次 `Buffer.Edit` 应用，可以整体撤销
- 重命名：先用 `prepareRename` 确认光标处可以改名，再用应用内对话框输入新名。`textDocument/rename` 的修改全部落在当前笔记时才作为一次 `Buffer.Edit` 应用；涉及其他文件时拒绝并提示，GoTyp 不在用户不知情时改写其他文件
- 标题跳转：`textDocument/documentSymbol` 中的标题按层级缩进，放进快速打开面板供筛选，选中后移动光标
- 异步：过期请求发送 `$/cancelRequest`

不接入的能力：

- 参数提示（`signatureHelp`）和内联提示（`inlayHint`）：悬停已能看到函数签名；常驻提示与极简界面冲突，MyGo 编辑器也没有参数提示浮层
- 快速操作（`codeAction`）：右键菜单是同步构建的，无法先异步取得结果；提供的重构对笔记价值不大
- 语义高亮、折叠范围、选区扩展：编辑器自带的分词高亮、折叠和选区已够用
- 文档链接、同名高亮：实测 tinymist 对笔记不返回结果
- 颜色：MyGo 编辑器没有显示色块的接口
- 全仓库符号、引用查找、跨文件重命名：会依赖或改写其他文件，超出单篇笔记的编辑范围
- lint、模板、包管理、PNG/SVG/HTML 等其他导出格式：笔记场景暂不需要

## PDF 导出

导出使用当前编辑快照：先把快照同步给 tinymist，再执行 `tinymist.exportPdf`，产物写入临时目录，复制到系统保存对话框选择的路径后删除，2 分钟超时。产物按文件名放在同一目录，不同目录下的同名笔记会互相覆盖，所以导出逐个进行。导出不改动 buffer、保存状态和预览。文档有错误时提示第一条错误。

tinymist 不是安全沙箱，GoTyp 面向用户自己信任的 Vault。

## 模块

```text
Native UI ── 应用状态与编辑会话
               ├── internal/vault      路径校验、扫描、读取、原子保存、冲突检查
               ├── Markdown 预览
               ├── Typst 预览（WebView）
               └── internal/tinymist   进程、JSON-RPC、文本同步、坐标换算、诊断、预览、编辑辅助、PDF 导出

后台结果 ── Window.Update ── 应用状态
```

`vault`、`tinymist` 不依赖 GUI，`tinymist` 也不依赖 MyGo，转换为编辑器类型在 `internal/gui` 中完成。Markdown 和 Typst 保留两条预览分支，不抽象通用渲染接口。

## 应用图标

应用图标由 `cmd/icon` 用 Go 画出，`mise run icon` 重新生成 `resources/icon.png`（正式版）和 `resources/icon-dev.png`（开发版），不手工编辑 PNG。

- 底板是 macOS 规格的连续圆角方块，颜色只带一点主题色，带软影、顶部柔光和内缘高光
- 图形是三块共用左下角、往右上逐层放大的方块，像一沓错落的纸；外两层是自带圆角的 L 形，层间留出露底板的缝
- 三层由外到内取主题色的浅、中、原色。正式版主题色是赭石 `#C0704A`；开发版换成青绿 `#1F8A80`，在程序坞里与正式版区分
- 只使用标准库和已有依赖 `golang.org/x/image`

## 测试

只测试防止数据损坏和异步竞争的部分：

- 文件层：原子保存、权限保留、外部修改冲突、路径与符号链接越界、重命名不覆盖
- tinymist：请求取消、过期结果丢弃、预览任务启动后过期时被结束、重命名涉及其他文件时拒绝、导出不向仓库写文件、UTF-16 与字节偏移换算（中文、emoji、行尾），使用受控 JSON-RPC 管道
- 界面：用 `ui.NewTester` 验证保存期间编辑仍为未保存、切换笔记不串用状态

异步测试使用受控任务和版本号，不依赖 sleep。每次实现后运行 `mise run fmt-check`、`vet`、`test`、`test-nocgo`、`build`。`ui.NewTester` 不渲染 WebView，Typst 预览只能在真实应用中检查：输入时实时刷新、双向滚动同步、切换笔记、多页文档、编译错误、浅色与深色外观、调色开关，以及 tinymist 缺失或崩溃；编辑辅助要在真实窗口中检查波浪线、跳转、格式化撤销和重命名对话框。涉及布局时还要检查中文输入、窗口缩放和长文件名。
