# GoTyp 设计

本文是 GoTyp 唯一的产品与架构设计文档。改变产品边界、数据格式、UI 技术路线、保存语义或 Typst 渲染方式时，先改本文，再改实现。

## 产品

GoTyp 是本地桌面笔记应用。用户打开一个文件夹作为笔记仓库（Vault），在单窗口中编辑 Markdown 或 Typst 源码并查看原生预览。仓库中的其他文件也列在文件树里：纯文本直接编辑，图片原生显示，其余格式交给系统默认应用。

- 打开、新建、切换、重命名、删除和保存 `.md`、`.markdown`、`.typ` 笔记
- 启动时回到上次的仓库和文件，`⌘P` 按文件名、路径和笔记标题快速打开仓库中的任意文件
- 两种笔记和其他纯文本文件共用一个源码编辑器，保存与冲突规则相同；非笔记文本只有编辑模式
- 图片（PNG、JPEG、GIF、WebP、SVG）只读显示；无法以文本打开的文件显示「在默认应用中打开」
- Markdown 支持编辑、分屏和预览模式
- Typst 支持后台编译、分页预览、错误展示、PDF 导出，以及基于 tinymist 的补全和悬停
- 自动保存不写坏原文件，不静默覆盖外部修改
- 监听仓库变化，侧栏和未修改的当前笔记跟随磁盘内容
- 所有界面和预览由 MyGo Native UI 绘制，不使用 WebView

不提供云同步、协作和账户体系。

## 技术基线

- Go `1.27.3`，MyGo 版本以 `go.mod` 为准，应用标识 `xin.liuyu.gotyp`
- Typst CLI `0.15.1`，只通过命令行调用，不引入 Typst 绑定、Rust 库或浏览器渲染
- tinymist（内置 Typst `0.15.1`），通过 stdio 上的 LSP 通信

`typst` 和 `tinymist` 都从 `PATH` 查找，不自动下载或捆绑。从图形界面启动时进程拿不到 shell 的 `PATH`，因此启动时把 `/opt/homebrew/bin`、`/usr/local/bin`、`~/.cargo/bin`、`~/.local/bin` 和 mise shims 目录中尚未包含的追加到 `PATH` 末尾（Windows 除外），不启动 shell 读取配置。

升级 MyGo、Typst 或 tinymist 后，重新核对本文涉及的 API、命令输出和协议行为。

## 固定决策

- 每篇笔记只用一种语法，由扩展名决定；不做 Markdown 与 Typst 的混排或互转
- 原始文本文件是唯一事实来源
- 单窗口文件夹仓库，不采用一篇笔记一个窗口的文档模型，因此不使用 `mygo.NewDocuments`
- 编辑器使用 `ui/editor`，Markdown 预览使用 `ui/markdown`，Typst 预览为 PNG 页面加 `ui.Image`
- PDF 只用于导出，不内嵌 PDF 阅读器
- Typst 编辑辅助只接 tinymist，不设计通用 LSP 层、渲染插件接口或第三方 UI 组件

## 首版不做

富文本所见即所得、混合渲染、标签与双链、全文搜索、多标签页、Typst 跳转定义等高级 LSP 能力和编辑器内诊断、云同步与插件、附件管理、滚动同步、未落盘编辑的崩溃恢复。

## 界面

界面风格参考 Linear：极简、紧凑，只用中性灰阶、细分隔线和少量图标区分层次，不放解释性文字。

- 视觉参数集中在 `internal/gui/theme.go`，强调色跟随系统；编辑器语法色和 Markdown 预览的配色也在这里显式给出，不依赖 MyGo 默认值
- 选中、悬停和按下都用文字色叠在底色上的中性浅底，强调色只用于光标、选区和焦点
- 只使用 MyGo 原生组件，不用 `ui.Painter` 或着色器绘制业务 UI，不自定义 Markdown 文档组件
- 图标使用内嵌的 Lucide 图标集（`internal/gui/icons`），纯图标按钮必须设置 `Label` 和 `Tooltip`
- Typst 语法高亮通过 `editor.Language` 分词器实现，行状态记录块注释、原始文本、跨行公式和括号嵌套

窗口隐藏系统标题栏，侧栏延伸到红绿灯下方，内容区顶部的文档头兼作标题栏：

```text
┌──────────────────┬───────────────────────────────────────────┐
│ ● ● ● ◧          │ notes / reading.md •           ✎ ◫ ◉   ⋯  │
│ ＋ 新建           ├───────────────────────────────────────────┤
│ 🔍 搜索        ⌘P │ 源码编辑器              │ 预览              │
│ ▾ notes           │                                           │
│   📄 reading.md   │                                           │
├──────────────────┤                                           │
│ 📁 仓库名       ⇅ ├───────────────────────────────────────────┤
│                  │ ✓ 12 ms                第 12 行，第 4 列  1,234 字 │
└──────────────────┴───────────────────────────────────────────┘
```

- 侧栏：宽度 180 到 420 DIP，默认 248，内容区至少留 360；`⌘B` 收放。顶部是「新建」（弹出新建菜单）和「搜索」（打开快速打开）两个入口，其下是 `ui.Outline` 文件树，底部是仓库切换。目录行不画展开箭头，只有文件夹图标（展开时 `folder-open`，收起时 `folder`）和名称，点击整行展开或收起；每深一层缩进一个图标的宽度，同一层的目录与文件图标纵向对齐；文件图标按扩展名取 Lucide 的 `file-*` 系列（笔记、代码、JSON、配置、脚本、图片、音频、视频、压缩包、表格），其余用 `file`。右键提供新建、重命名、复制路径、在默认应用中打开、在文件管理器中显示、移到废纸篓
- 文档头：左侧目录和文件名，未保存时显示圆点；右侧是编辑、分屏、预览分段（`⌘1`、`⌘2`、`⌘3`，只对笔记显示）和「更多」菜单。分屏宽度不足时改为上下布局
- 状态栏：28 DIP 高。左侧是 Typst 编译状态（耗时、错误或警告计数，点击展开诊断面板）和后台活动；右侧是光标位置或选区、字数、Typst 页数。平时用次要文字色，只有错误和警告着色
- 冲突和保存失败用编辑区上方的常驻提示行展示，并提供对应操作
- 新建笔记不弹对话框，在当前目录创建「未命名」笔记；重命名用应用内对话框，只改文件名；删除移到系统废纸篓，不弹确认
- 专注模式隐藏侧栏、文档头和状态栏，只在会话内有效
- 打开仓库、另存为副本和导出 PDF 使用系统文件对话框；窗口尺寸和位置由 MyGo 保存
- 动效只用于反馈，不推动预览页面

## 数据

Vault 是普通文件夹，GoTyp 不向其中写入任何自己的文件。应用状态保存在用户配置目录的 `GoTyp/state.json`，包括最近仓库，以及按仓库区分的当前笔记、编辑模式、侧栏、分栏比例和行号设置；文件损坏时回到默认状态。Typst 临时文件放在系统临时目录，目录名带进程号，下次启动时清理已不存在进程的目录。

- 文件 ID 是相对 Vault 根的规范化路径，统一用 `/` 分隔
- 扫描列出全部文件，只有 `.md`、`.markdown`、`.typ` 是笔记
- 以文本打开的文件不超过 10 MiB，且是不含 NUL 的合法 UTF-8；否则不进编辑器，避免保存时改坏非文本内容。笔记同样适用
- 图片不超过 20 MiB，在后台解码，长边缩到 4096 像素以内
- 笔记标题取第一个一级标题（Markdown `#`、Typst `=`），没有时用文件名，只用于快速打开匹配；只读文件开头 4 KB
- 扫描忽略以 `.` 开头的条目，跳过无法读取的目录，不跟随逃出 Vault 的符号链接
- 用 `mygo.WatchFiles` 递归监听：结构变化时后台重新扫描；当前笔记被外部修改时，无未保存编辑就静默重载，否则进入冲突；自己保存产生的事件按文件状态识别并忽略
- 重命名只在同一目录内进行，目标已存在时拒绝；扩展名可以改，改后按新扩展名决定打开方式

## 保存与冲突

保存写入 `editor.Buffer` 的不可变快照，文件 I/O 在后台执行。

- 停止编辑 1 秒后自动保存，持续编辑时最迟 10 秒保存一次；手动保存、切换笔记、关闭和退出时立即保存
- 写入同目录临时文件后原子替换，保留原文件权限，替换后同步目录
- 保存结果携带开始时的 buffer 版本，只有该版本仍是当前版本才标记为已保存
- 写入失败时保留编辑并提示，5 秒后重试
- 每次读取或保存后记录文件标识、修改时间和大小，保存前重新核对。不一致时进入冲突，停止自动保存，由用户选择重新加载、覆盖或另存为副本；文件被删除时可重新创建、关闭或另存为副本
- 切换、重命名或删除当前笔记前先在后台保存，失败则留在原笔记。退出时保存失败，用系统对话框询问取消还是放弃修改

原子替换只防止写出半截文件，不提供崩溃恢复。

## 编辑状态与异步任务

当前笔记维护一个编辑会话：笔记 ID、类型、`editor.State`、buffer 版本、已保存版本、保存状态和预览状态。图片或无法以文本打开的文件没有编辑会话，只保存文件 ID 和后台读取的结果。

- `editor.State`、列表状态和预览数据保存在应用状态中，不保存 `ui.Element` 或 `*ui.Context`
- 有状态控件使用笔记路径等稳定 key
- view 中不做 I/O、编译或解码，也不无条件启动任务
- 后台任务只读快照，结果经 `Window.Update` 回到主线程，应用前核对笔记 ID 和源版本，过期即丢弃
- 窗口关闭、切换笔记或新任务到来时取消不再需要的工作

## Markdown 预览

预览读取当前编辑快照，使用 `markdown.View` 默认主题和组件，阅读宽度约 720 DIP 居中。本地图片通过 `markdown.FileImages` 按笔记目录解析，不下载远程图片。

链接处理：页内锚点交给 Markdown 组件；Vault 内的笔记在 GoTyp 中打开；`http`、`https`、`mailto` 和 Vault 内其他文件交给系统打开；不存在、逃出 Vault 或无法识别的目标只提示错误。

## Typst 预览

预览读取当前编辑快照。相对资源按笔记的逻辑位置解析，项目根固定为 Vault。

每篇 Typst 笔记首次预览时启动一个常驻 `typst watch` 进程，利用其增量缓存；切换笔记、仓库或退出时结束。Unix 上由一个 sh 守护脚本启动，GoTyp 退出导致管道关闭时结束 typst，不留孤儿进程。

进程在临时目录的镜像仓库中运行：从 Vault 根到笔记目录这一路是真实目录，其余条目是指向原仓库的符号链接，主文件写入编辑快照。这一路的目录结构变化时重建镜像并重启进程。输出为 `page-{p}-of-{t}.png`。

1. 编辑停止 150 毫秒后，把快照原子写入主文件；内容未变时跳过
2. 以 stderr 中的 `compiled successfully`、`compiled with warnings`、`compiled with errors` 判断编译结束，其后的行为诊断
3. 成功后按最新文件确定页数，只重新解码变化的页面，删除旧页
4. 笔记和快照版本都匹配时才替换预览；失败时保留上一份成功预览并显示错误
5. 30 秒无状态行或进程意外退出时重启；连续两次失败后改为每次调用 `typst compile`
6. 编译超过 300 毫秒才显示进度

页面用 `ui.List` 和 `ui.Image` 在浅灰画布上展示。还没有成功预览时，错误直接显示在预览区。找不到 `typst` 时源码仍可编辑和保存。选择 PNG 而非 SVG，是因为 MyGo 的 SVG 支持不完整。

typst watch 的 stderr 不是稳定接口，升级 Typst 后需重新核对；无法识别时按第 5 步退回一次性编译。大型多页文档的位图内存是已知风险，出现问题后再改为只解码可见页面。

## Typst 补全与悬停

补全和悬停由 tinymist 提供，使用 `editor.State` 的 `OnCompletion`、`ShowCompletions`、`OnHover`、`ShowHover`，不自绘。tinymist 与预览、导出互不依赖；缺失、崩溃或返回异常只失去这两项能力。

- 进程：每个仓库最多一个 `tinymist lsp`，首次打开 Typst 笔记时启动，`rootUri` 为 Vault；`exportPdf` 设为 `never`，关闭未使用的能力；服务端请求都要回应。意外退出后重启一次，再失败就停用到下次打开仓库
- 同步：打开笔记时 `didOpen`，切走或删除时 `didClose`，两者在同一后台队列按序执行。补全或悬停前若 buffer 版本更新，先发全量 `didChange`；比已发版本旧的请求直接放弃
- 坐标：tinymist 使用 UTF-16 行列，编辑器使用 UTF-8 字节偏移，换算在 `internal/tinymist` 中基于对应版本的快照完成；越界或落在字符中间时丢弃整次结果
- 补全：前缀含非 ASCII 字符时不自动请求，`Ctrl+Space` 可主动请求。`textEdit` 起点须与编辑器起点一致，否则裁剪或丢弃；片段用 `editor.ParseSnippet` 解析；`Documentation` 只放第一段纯文本摘要；按 `sortText` 稳定排序
- 悬停：结果用 `markdown.View` 显示
- 异步：结果应用前核对笔记 ID、buffer 版本，补全还要核对光标位置；过期请求发送 `$/cancelRequest`

## PDF 导出

导出使用当前编辑快照，通过系统保存对话框选择路径，独立一次性编译，2 分钟超时。导出不影响 buffer、保存状态和预览。

Typst CLI 不是安全沙箱，GoTyp 面向用户自己信任的 Vault。

## 模块

```text
Native UI ── 应用状态与编辑会话
               ├── internal/vault      路径校验、扫描、读取、原子保存、冲突检查
               ├── Markdown 预览
               ├── internal/typst      watch 进程、编译、PNG 预览、PDF 导出
               └── internal/tinymist   进程、JSON-RPC、文本同步、坐标换算

后台结果 ── Window.Update ── 应用状态
```

`vault`、`typst`、`tinymist` 不依赖 GUI，`tinymist` 也不依赖 MyGo，转换为编辑器类型在 `internal/gui` 中完成。Markdown 和 Typst 保留两条预览分支，不抽象通用渲染接口。

## 测试

只测试防止数据损坏和异步竞争的部分：

- 文件层：原子保存、权限保留、外部修改冲突、路径与符号链接越界、重命名不覆盖
- Typst：语法错误、进程取消、状态行与诊断解析，不依赖本机 Typst
- tinymist：请求取消、过期结果丢弃、UTF-16 与字节偏移换算（中文、emoji、行尾），使用受控 JSON-RPC 管道
- 界面：用 `ui.NewTester` 验证保存期间编辑仍为未保存、过期预览被丢弃、切换笔记不串用状态

异步测试使用受控任务和版本号，不依赖 sleep。每次实现后运行 `mise run fmt-check`、`vet`、`test`、`test-nocgo`、`build`。涉及布局时还要运行真实应用，检查浅色与深色外观、中文输入、窗口缩放、长文件名、多页预览和错误状态。
